# 장애 대응 런북

> 교육용 더미 데이터입니다.

## 1. 등급 판정

P1은 고객 결제·인증이 불가능한 상태입니다. 즉시 대응하며 15분 내 상황을 공유합니다.
담당자는 대응 채널을 개설하고 30분마다 진행 상황을 갱신합니다.

P2는 일부 기능이 저하되었으나 우회가 가능한 상태입니다. 1시간 내 대응합니다.
우회 방법이 있으면 고객 안내를 먼저 하고 근본 조치를 진행합니다.

P3은 내부 도구나 배치 작업의 문제로 고객 영향이 없습니다. 다음 영업일에 처리합니다.

P4는 정보성 알람이며 별도 대응이 필요하지 않습니다. 다만 같은 알람이 하루 10회를
넘으면 알람 임계값 재조정 대상으로 등록합니다.

## 2. 5xx 급증 시 확인 순서

첫째, 최근 30분 내 배포 이력을 확인합니다. 배포 직후라면 롤백을 우선 검토합니다.
배포 이력은 파이프라인 대시보드와 변경관리 티켓 양쪽에서 교차 확인합니다.

둘째, 의존 서비스의 상태 페이지를 확인합니다. 외부 결제 게이트웨이나 인증 제공자의
장애가 원인인 경우가 많습니다. 이 경우 우리 쪽 롤백은 도움이 되지 않습니다.

셋째, 데이터베이스 커넥션 풀 사용률을 확인합니다. 사용률이 90%를 넘으면
커넥션 누수를 의심하고 최근 배포된 쿼리 변경을 살펴봅니다.

넷째, 위 셋으로 원인이 좁혀지지 않으면 애플리케이션 로그에서 예외 스택을 수집해
가장 빈도가 높은 예외부터 조사합니다.

## 3. 롤백 기준

오류율이 5분 이상 1%를 초과하고 직전 배포가 2시간 이내이면 롤백합니다.
롤백은 배포 담당자 단독으로 수행할 수 있으며, 사후에 변경관리 티켓을 남깁니다.

데이터베이스 스키마 변경이 포함된 배포는 단순 롤백이 불가능합니다.
이 경우 즉시 DBA를 호출하고 순방향 수정을 검토합니다.

롤백 후에는 반드시 오류율과 지연 시간이 정상으로 돌아왔는지 15분간 관찰합니다.
